// One file to rule it

Config that reads like a sentence.

  • halyard.toml — declare regions, routes and storage in one place, checked into your repo.
  • Zero-downtime — traffic shifts to the new build only once health checks pass.
  • Reproducible — the same file deploys identically from your laptop or CI.
halyard.toml 
# the whole deployment, version-controlled
app = "aurora-api"
runtime = "node@22"

[scale]
regions   = "auto"   # follow your traffic
min_ready = 1
max       = 80

[store.sessions]
type = "edge-kv"
ttl  = "24h"

[build]
command = "npm run build"
output  = "./dist"

// From zero to live

Three steps. No meeting required.

1

Connect your repo

Point Halyard at a Git repository or run halyard init locally. It detects your framework automatically.

2

Push a branch

Every commit builds and deploys to an isolated preview URL you can share with anyone on the team.

3

Merge to go global

Merging promotes the exact build you reviewed to production across all 213 regions. No rebuild, no surprises.
